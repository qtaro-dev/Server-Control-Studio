# Windows配布の検証と公開条件

開発ソースと自作サンプルコードは同じPublicリポジトリでMITライセンスにより公開します。第三者ソフトウェア、画像、商標にはそれぞれの条件を適用します。Windows x64の配布物は条件を満たした形式をGitHub Releasesから無料配布します。

## ローカル候補

- 既存のプロジェクト専用npmでテスト、監査、ビルドを実行します。手動のrelease-validationワークフローも公開操作を行わずに候補を検証します。
- 同梱検証は、現在の公開ツリーから外した旧ロゴ原本を監査時のGit履歴から読み取って照合します。ローカル検証には履歴を取得したクローンを使用します。
- Installer・Portableを同じコミットからビルドし、形式別に実EXEの外側とアプリペイロードを検査します。ソースコミット、同梱物、SHA-256を候補に紐づけます。
- [第三者著作権表示](../../THIRD_PARTY_NOTICES.txt)には、出典、同梱物および残る配布条件を記載しています。
- `node scripts/prepare-public.cjs <release内の出力親>` は配布文書と配布ファイル用の空ディレクトリをローカルに準備します。

## EXE公開条件

`node scripts/verify-release.cjs --assert-ready` は、画像の権利、第三者配布条件、最終公開承認が全て確認された時点で成功します。必須CIと検証の成功に加え、対象形式の対応ソース、ビルド情報、ライセンス通知を同じ配布ページから取得できるようにします。

未署名EXEではWindowsの警告が表示される場合があります。Release Notesは日本語で、該当する配布形式、SHA-256と検証手順、対応ソースの取得先を記載します。
