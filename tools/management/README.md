## 起動と操作

プロジェクト直下で `npm start` を実行し、4番目の **Docker環境管理** タブを開きます。別ウィンドウや重複したメニュー起動項目はありません。既存3タブの入力・生成・保存状態とは分離して管理状態を保持します。

左側はプロジェクト名・サービス概要・保存先の一覧と登録/再読込/登録解除、右側は概要と「構成・不足診断」「ファイル編集」「Docker操作・ログ」「詳細設定」の内部タブです。Compose名・Context・Compose順序・.env選択は詳細設定にまとめています。管理タブだけ横幅/高さを広く使い、左右ペインと内部パネルでスクロールします。既存3タブの幅やスクロール方式は変えていません。

配色はメイン画面の共通テーマとCSS変数に追従し、専用のテーマ管理はありません。選択プロジェクト・選択内部タブを強調し、状態は「正常」「注意」「エラー」の文字と色で区別します。不足診断はパス単位で理由を統合し、必須/任意を分類します。任意の.envは必須件数に含めず、補完操作/補完できない理由を該当ファイルに表示します。

1. 「プロジェクトを登録」でCompose YAMLを選択します。同じ親フォルダの複数ファイルも選択でき、画面の「Composeの順序」で基底→上書き順に並べ替えられます。
2. Composeの親フォルダ・サービス名・実行用プロジェクト名・Contextを確認します。既定名は.envのCOMPOSE_PROJECT_NAME、Composeのname、フォルダ名の順で解決します。外部ツールで別名起動している場合は「実行対象を保存」で合わせてください。
3. Windowsの初期Contextはdesktop-linuxです。既定Context自体は変更しません。任意のContextを使う場合はそのプロジェクトの欄を変更して保存します。
4. 必要ならプロジェクト内の.env系ファイルを選択します。未選択時はComposeの標準どおり親フォルダの.envが使われます。サービスのenv_fileも診断します。内容は画面に表示しません。
5. 「構成・不足診断」で参照先を調べます。登録・一覧表示・診断だけではDockerを実行しません。
6. 「ファイル編集」で対象を開き、編集後に「変更差分を確認」。強調された変更前後を確認し、「検証・バックアップして保存」を押します。Composeは候補ファイルでdocker compose config -qが成功しない限り保存しません。
7. 「Docker操作・ログ」からEngine接続確認・構成検証・起動・停止・再起動・ビルド・再構築・状態・ログを操作します。起動/停止/ビルド等は対象Context・名前・ファイル・作業場所を確認するダイアログが出ます。
8. 「登録解除」は一覧から除外するだけです。元ファイル・コンテナ・ネットワーク・ボリュームは削除しません。

登録情報はElectron userDataの`compose-management/projects-v1.json`に保存します。編集バックアップは同じuserData側の`compose-management/backups/<プロジェクトのハッシュ>/<保存ごとのID>/`へ保存し、DockerのCOPY対象や公開ディレクトリに混入させません。成功時は実際のバックアップパスを表示します。

## 責務分離

- `app/management/projects.js`：登録・一覧・再読込・実行対象設定・登録解除。
- `safe.js`：YAML解析、サイズ/循環/危険キー制限、プロジェクト内パスとリンク検査、機密行の非表示/復元、ログ秘匿。
- `diagnostics.js`：Dockerfile、COPY/ADD、マウント、env_file、configs/secrets参照の不足診断。既知のNode.jsサンプル補完。
- `diagnostic-view.js`：パス表記の正規化、重複理由の統合、必須/任意の表示用整理。
- `editor.js`：編集セッション・変更確認・構文確認・競合検知・バックアップ・原子的な置換。
- `docker.js`：固定操作の引数配列、Context/Compose/作業場所の指定、出力/時間制限、失敗案内。シェルは使いません。
- `main.js`：既存メインウィンドウの送信元検証を使う管理IPC・ネイティブ確認ダイアログ。独立ウィンドウ生成処理は撤去。
- リポジトリ直下`preload.js`：既存APIとは別の名前空間に用途限定のmanagementAPIを公開。生IPC・任意コマンドは公開しません。
- `app/index.html`、管理側`renderer.js`、`style.css`：4番目のメインタブ内の登録一覧・診断・編集/差分・Docker操作・詳細設定。不要な管理側index.html/preload.jsは撤去。

既存main.jsは管理IPCの初期化を担当します。既存のモジュール選択・生成・保存・テーマ・設定は維持し、管理の編集機能を生成結果タブへ混在させていません。YAML解析用のproduction依存はyaml 2.9.1です。配布内容の検査スクリプトも依存同梱を確認するよう更新していますが、配布EXEは未ビルドです。

## 安全性

- nodeIntegration=false、contextIsolation=true、sandbox=true、webSecurity=true、専用の厳格CSPを維持。
- 既存のassertTrustedSenderでメイン画面の固定URL・main frame・webContentsを照合する用途限定管理IPC。サブフレーム・別送信元・不正な操作を拒否。CSPやウィンドウの権限設定は変更していません。
- Dockerはshell:falseの引数配列。操作は固定許可リストだけで、手入力コマンド、down、rm、prune、ボリューム削除機能はありません。
- 起動やビルドはComposeが指定したイメージ/コード/ホストマウントを利用します。信頼する構成だけ実行するよう、明示確認します。
- 編集可能なのは登録したプロジェクト内で診断に現れる通常ファイルだけ。リンク、外部パス、.git、機密ファイルを拒否します。
- .env/秘密鍵やsecrets参照ファイルの内容は編集画面に出しません。Compose等の機密行は非表示プレースホルダーで保持し、変更/削除/複製を拒否します。
- 編集前と保存直前に原本のハッシュを検査。別プロセスの変更があれば中断します。バックアップと一時ファイルを用いて置換し、失敗時は原本/バックアップを保持します。
- 補完は現行生成器の固定Node.js Dockerfileと完全一致し、package.json・lockfile・起動ソースが未作成の場合だけ。追加内容を提示して同意後、既存ファイルを上書きしない方法で保存します。
- 登録時のDocker実行・ネットワーク接続・自動補完はありません。GitHub連携機能は追加していません。

## 初期版の制約

現行操作は[利用者向けの操作ガイド第11章](../../docs/manual/index.html#management)を参照してください。4タブ・一式保存・登録/診断/補完・編集/バックアップ・Docker操作・詳細設定の実画面を掲載しています。新規Composeからversion属性を除去する変更も含みます。上記2026-10-29の検証記録は当時の結果であり、文書更新だけでDockerの再起動試験を行ったという意味ではありません。

- 同時登録するComposeは同じ親フォルダ内・最大10件。ファイルの追加/削除は再登録で行い、画面では既存セットの順序だけ変更できます。
- 外部ディレクトリのbuild contextやマウント、変数を含むパス、include/extends、動的COPY/ADDは推測で補完しません。Docker構成検証と利用者の確認が必要です。
- サービス一覧/不足診断の静的統合は、Composeの全マージ規則を再実装するものではありません。実際の検証/起動は指定したCompose順序とDocker自身の解決結果を使用します。
- サンプル補完は依存なしのNode.js HTTPアプリだけです。既存アプリのlockfileや業務ソース、未知の外部構成は生成/置換しません。
- .env・秘密鍵・機密行の編集は初期版の対象外。非表示値の変更が必要な場合は外部エディターで安全に行ってください。
- Dockerfile・一般設定は静的構文確認が中心で、実際のビルド/起動を保証しません。構成によっては追加のソース・依存が必要です。
- ログの秘匿は既知の設定値と一般的な秘密値表現が対象です。アプリ独自の未知の秘密情報まですべて検知する保証はありません。共有前に確認してください。
- 長時間処理は時間/出力量で制限します。タイムアウト時にはDocker側の状態を再確認してください。常時監視や自動復旧、任意の管理コマンドは追加していません。
- 今回はWindowsのローカルDockerで上記専用構成を確認しました。全35レシピのDocker再検証、他OSでのGUI、配布版での新画面は未検証です。
